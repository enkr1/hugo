# GitHub Profile README Revamp — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `enkr1/enkr1/README.md` with an editorial Ba Zi–themed profile that mirrors `blog.enkr1.com`, built around a programmatically generated animated SVG hero.

**Architecture:**
The profile README references a single static SVG file (`assets/hero.svg`) committed to the same repo. The SVG is generated by a Node script (`scripts/generate-hero-svg.mjs`) that uses `opentype.js` to convert display text to vector `<path>` elements at build time — this removes any runtime font dependency on GitHub's renderer. Waveform animation uses SVG SMIL `<animate>` tags (no JavaScript, natively rendered by GitHub's `camo` image proxy). Fonts (Cormorant Garamond, Noto Serif SC) are committed as TTF files used by the generator only.

**Tech Stack:**
- Node.js 20+ (built-in test runner `node:test`, ESM modules)
- [`opentype.js`](https://opentype.js.org/) v1.3+ for font → path conversion
- Vanilla SVG with SMIL animation
- GitHub profile README rendering (via `raw.githubusercontent.com` + `camo` image proxy)

**Spec reference:** `docs/superpowers/specs/2026-04-09-github-profile-readme-revamp-design.md`
**Mockup reference (source of truth):** `docs/superpowers/specs/assets/2026-04-09-hero-mockup.html`

const OUTPUT_PATH = resolve(__dirname, '../assets/hero.svg');

export async function generateHeroSvg() {
  const svg = '<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1280 580"></svg>';

// Allow direct execution via `node scripts/generate-hero-svg.mjs`

```javascript
import opentype from 'opentype.js';

/**
 * Load a font from disk and convert a text string to an SVG <path> element.
 * The returned markup has text converted to vector paths — no font dependency
 * at render time.
 *
 * @param {object} opts
 * @param {string} opts.fontPath — Absolute path to TTF/OTF file
 * @param {string} opts.text — Text to convert
 * @param {number} opts.x — X coordinate (in viewBox units)
 * @param {number} opts.y — Y coordinate (baseline, in viewBox units)
 * @param {number} opts.fontSize — Font size in viewBox units
 * @param {string} opts.fill — Fill color (hex)
 * @param {number} [opts.letterSpacing] — Additional spacing between characters in viewBox units
 * @returns {Promise<string>} SVG <path .../> element as a string
 * @throws {Error} If the font fails to load or produces empty path data
 */
export async function textToSvgPath({ fontPath, text, x, y, fontSize, fill, letterSpacing = 0 }) {
  const font = await opentype.load(fontPath);
  const path = font.getPath(text, x, y, fontSize, { letterSpacing: letterSpacing / fontSize });
  const d = path.toPathData(2);
  if (!d || !d.startsWith('M')) {
    throw new Error(`textToSvgPath produced invalid path data for "${text}" — ${d.slice(0, 30)}`);
  }
  return `<path d="${d}" fill="${fill}"/>`;
}
```

**Note on letterSpacing:** `opentype.js` `getPath()` accepts a `letterSpacing` option as a fraction of the em square. We pass `letterSpacing / fontSize` so callers can think in viewBox units.

  // Cream paper background (月影白)
  parts.push('<rect width="1280" height="580" fill="#FBF8F3"/>');

  // glyphs for. We render this corner with Noto Serif SC instead, which handles both Latin and CJK.
  // Trade-off: slight visual inconsistency (Noto's Latin vs the italic Cormorant used elsewhere) —
  // acceptable at 14px, preserves the Ba Zi seasonal glyph. letterSpacing value may need tuning
  // during Task 11 visual verification since Noto's Latin metrics differ from Cormorant Italic.
  parts.push(await textToSvgPath({
